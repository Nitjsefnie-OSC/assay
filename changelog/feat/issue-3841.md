### Fixed
- statusgen's held scan now supersedes earlier Evidence entries as wholes once the final entry carries a live strict `VERIFY: PASS` and re-ran every row key of every earlier entry clean: their prose, entry-level `VERIFY: BLOCKED` lines, held or could-not-check notes that name no row or name a row absent from every keyed table, and holds in fenced code or wholly inside an HTML comment are dropped. A comment counts only where the renderer opens one: `<!--` at three spaces of indentation or fewer and no tab, ended by the first `-->` or `--!>` from its first byte, so `<!-->` and `<!--->` close on their own line. After a `--!>` end, the rest of the HTML block up to `-->` renders live and stays read. Partial coverage still refuses: an earlier key the final entry did not re-run, or re-ran to a failure, an earlier results row that cannot be aligned or keyed, or an earlier entry with no keyed row keeps every entry read. So does an earlier entry that records a row in a table the scan cannot key, even inside an HTML comment (another shape, no separator row, no leading pipe, a blockquote, an HTML table, including one nested in a results table's cell, or a line continuing a results table), or an HTML block that leaves a tag, a quoted attribute value or a comment open where the page ends it (on the opener line when it closes there, and at any line that leaves a blockquote or list item), which hides what follows on the page. A carriage return with no line feed after it, which ends a line on the page, turns whole supersession off from that line on. A hold in any other HTML block is always read.
