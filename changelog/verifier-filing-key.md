### Fixed
- A verifier's failed or blocked verification is now filed once per case. `deskfile new` accepts `--filing-brief` and `--filing-case` (with `--raised-by`), derives an exact filing key from the repository, canonical brief, raising role and case id, and stamps it into the filed issue. Before the title matcher runs it looks that key up among open issues in the same repository raised by the same role: a hit refuses the filing and names the existing issue, so a repeat observation under a different title no longer files a second issue. A search that fails or is truncated files nothing, and an ambiguous create is reconciled by the same lookup before any further create. Filings without an identity keep the title matcher, and `--force-new --reason` stays the audited override.
- The verification loop reconciles a re-landed failure to the issue already filed for its case before filing, using the forge read it already owns.
